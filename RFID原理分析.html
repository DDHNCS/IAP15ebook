1 · RFID 是什么：定义与三要素

RFID（Radio Frequency Identification，射频识别）是利用无线电磁波，不接触即可自动识别目标并读写其携带数据的自动识别技术。“认出是哪张卡”的那串独有数字，就是它存的标识（UID / EPC）。

任何 RFID 系统都有三要素：
要素作用本案例对应
① 读写器 Reader辐射射频场、发指令、解调应答蓝色 PCB（主控 + RC522 + 天线）
② 标签 Tag存标识与数据，按是否带电池分有源/无源S50 白卡 / 钥匙扣
③ 应用系统把“读到的卡号/数据”用起来你的 main.c 逻辑、门禁/考勤

读 UID 只是入口；RFID 真正的价值在能对标签内存读写一个属于你的数据块。

2 · RFID 怎么分类

按工作频率（决定读距与形态）

频段典型频率读距典型用途对应本项目
LF 低频125 kHz约 ≤10 cm老门禁、动物耳标—
HF 高频13.56 MHz约 1–10 cm门禁、公交 MIFARERC522 / S50 就是 HF
UHF 超高频860–960 MHz1–10 m物流、仓储、车牌—
微波2.45/5.8 GHz数十 m不停车收费 ETC 等—

频段越高通常读距越远；但越高越易被金属/水吸收。

按供电方式（决定卡能否“自己说话”）

类型供电能否主动发信号读距代表
无源 Passive从读写器磁场取能否（靠负载调制回传）近S50 卡（本项目）
半有源 Semi自带电池维持芯片弱中温湿度记录卡
有源 Active自带电池可主动发送远车联网、追踪器

RFID（含 S50）大多是无源——这是第 3 节的关键。

3 · 无源标签从哪取电：电磁感应

实物：S50 非接触式卡
上下两层为 PVC 卡片基材；
中间金色矩形即 卡内线圈（绕 N 圈）；
线圈中央的小方块为 IC 芯片 + 谐振电容；
整体构成 LC 谐振回路 @ 13.56 MHz，无电池。
实物：RFD-RC522 模块
右侧铜走线即 机内 PCB 天线（黄色虚线圈出区域）；
左下 SOIC 封装为 NXP MFRC522 主控芯片；
左侧 4×2 排针：SDA/SCK/MOSI/MISO/IRQ/GND/RST/3.3V；
上方绿色 LED 为电源/通信指示，读卡时常亮或闪烁。
②　S50 卡内线圈切割磁感线 → 感应出交流电压 → 整流成直流 → 卡内芯片被"唤醒"，可以执行指令并通过负载调制回传数据（见第 5 节）。
图 3-1　RC522 实物模块 + S50 白卡的电磁感应取电：把白卡平行贴近模块右侧 PCB 天线区（黄色线圈位置），模块辐射的 13.56 MHz 交变磁场穿过卡片内部的金色线圈（中间层），感应出的电压经整流后给卡内 IC 芯片供电。

为什么是 LC 谐振

卡片电容+线圈构成 LC 回路，谐振到 13.56 MHz 让感应电压最大。卡片越贴、越平行于天线，耦合越强、电量越足。

同一个场：既供电又传数据

芯片被激活后，既能执行指令，也能在同一个场里“负载调制”回传数据（见第5节）。无源卡既是“被供电的”又是“会发声的”。

工程上为什么读距只有 1–3 cm：稍远磁场就变弱、电压不够“唤醒”；卡下方垫金属会吸收磁场。这是无源 HF RFID 的物理本质，不是故障。

4 · 前向链路：读卡器 → 标签（发命令）

读卡器“喊话”给卡，靠的是把载波(13.56MHz)做成随数据变化的幅度开关，并用一种约定的编码打包成卡片能听懂的“帧”。两种要素对应两种概念：调制(把数据装到载波上)与编码(用什么波形表达 0/1)。

概念14443A 前向怎么实现一句话
调制100% ASK（幅度键控，载波有/无）“有载波=1、没载波=0”地装数据
编码Miller 编码用脉冲位置表达位，省能、好解调

图 4-1　前向链路：把“命令字节”编码再放到 13.56MHz 载波上，用幅度开关方式送往标签。RC522 已在内部代你做这些，只需你写要发的字节。

5 · 反向链路：标签 → 读卡器（回数据）

无源标签电量太弱，不可能像手机那样“自发”反向电波。它的技巧是负载调制：标签内有一个受数据控制的开关电阻，按数据瞬间“改变自身对磁场的‘吃电量’”，这个变化会以微小幅度反射回读卡器天线。

标签端做了什么

数据 1/0 控制一个负载在“接”与“断”之间来回，于是标签线圈从磁场吸取的能量忽高忽低 → 在磁场里制造“扰动”。

读卡器端听到了什么

RC522 的高灵敏前端把这个微弱扰动放大、解调（副载波/Manchester 变换）后还原成字节，放进它直通到主控 FIFO 的两 bytes——你看到“UID”就是这么回来的。

常见疑问：读距近除了供电问题，更因为反向是“被动反射”信号极弱，必须靠得很近才会被可靠解调。这也是为何超高频 UHF 用主动反向、读距更远。

6 · 一次识别：ISO14443A 与 RC522

卡片类(13.56MHz)按 ISO/IEC 14443 通信。RC522 是其中的 Type A 实现。把“一次读卡号”拆成对读卡器可见的几个帧，是理解驱动代码的基础。

图 6-1　ISO14443A 的识别剧本：短帧寻卡 → ATQA 类型 → 整字节防冲突 → 拿回 UID+BCC。识别完成后才谈“选卡、鉴权、读写块”。

识别到 UID 只是“知道你是谁”。若还要读写你的数据，需要继续 Select(选中) → AuthState(密钥鉴权) → Read/Write(读写块)。RC522 手册把这些封装成一组命令 + 状态机，你要按顺序走。

7 · RC522 内部：主控只写寄存器

RC522 把所有射频层复杂度封装成寄存器。它内部是一个 MFRC522 状态机：主控写命令寄存器 → RC522 自动收/发 / 校验 / 处理冲突 / 定时超时，结果放在 64 字节 FIFO 里，主控再读回即可。

驱动里常见的“读写一个寄存器”

写寄存器(CommandReg, 0x0F); // 软件复位
写寄存器(FIFODataReg, REQA); // 把一帧发出去
等中断(ComIrqReg);            // 等超时或收到
读FIFO → 得应答字节            // 卡片回的内容

向下：把帧交给射频

你在 FIFO 里放“REQA”等字节，RC522 会替你做 Miller 编码 + 100%ASK + 上到 13.56MHz 的无数载波周期。你写的是“命令”，它做的是“波”。

向上：把波译成字节

它把自己的 13.56MHz 场里的“负载调制扰动”解调成数据放进 FIFO。你读的字节，其实是远方卡片极微弱“反射”出来的结果。

为什么 “读 Version=0x92” 不等于能读卡：读版本只证明“SPI 上下行通、寄存器能访问”；读卡还要 RC522 的天线真的能把 13.56MHz 场送出去并收回来（初始化必须把 TxASK、功率、天线开关都配好）。两类问题的修复方向完全不同。

8 · 数据在卡里怎么存（MIFARE Classic）

一句话内存图

扇区块内容
扇区 0块 0厂商块（含 UID，只读）
扇区 N块 1/2用户数据（16 B/块 可读写）
块 3扇区尾：KeyA/控制/KeyB

S50 = 16 扇区 × 4 块 × 16 B ≈ 1 KB（经典结构）。

每扇区有一把“锁”

读写某扇区的数据块前，须用该扇区的密钥鉴权。有 16 个扇区，就有 16 组独立密钥，扇区间权限互不相通——这就是“不同商家能共用一张卡而不互相越权”的基础。

9 · 安全与局限

RFID 能做的三件事

① 唯一标识（UID）→ 门禁/考勤“你是谁”；② 存数据（扇区读写）→ 余额/卡号/通行权限；③ 密钥鉴权 → 只有持正确密钥的读写器能碰某些扇区。

现实局限（务必清楚）

局限说明 / 应对
MIFARE Classic 加密已偏弱曾被破解演示；教学/一般门禁足够，但不建议用于高安全支付/身份证级别的正式场景。高安全请用 DESFire、SE 等更先进标签。
UID 可被克隆（复制）只靠 UID 不放行的门禁有“复制卡”风险；务必叠加写入端数据与密钥。
读距短、怕金属/水物理决定，选正确频段/天线与环境才稳。
写扇区尾风险写错 Key/控制位会永久“锁死”扇区，别乱改块3（厂商/控制块）。

10 · 应用与选型速查

需求推荐配置说明
教学 / 门禁原型（本项目）RC522 + S50，HF 13.56MHz便宜、资料多，SPI 驱动简单
高频门禁正式升级到 MIFARE Plus / DESFire更强密钥、更抗克隆
仓储 / 物流远距UHF 读卡器 + EPC tag、860-960MHz多标签读取、远距盘点
短距、卡贴在机ISO14443A/NFC 型标签手机兼容性好
给你一句话总结：RFID = 读写器辐射电磁场 → 无源卡靠“感应取电”被唤醒 → 通过“载波幅度(前向)”与“负载调制(回向)”进行一问一答 → 最后以一个稳定 UID 收尾。写驱动时只需“写命令字节 + 设对位长 + 读回 FIFO”，而那个最容易被坑的“每类命令该用多少位”在第 5/6 节给了答案。
